1. Business context

Architecture 2 tests the hypothesis that a modern transcription model plus one well-governed LLM call beats a chain of managed cognitive services on both accuracy and price, without giving up real-time latency.

Objectives

  • Halve the word error rate of the classic recognizer at equivalent streaming latency
  • Collapse redaction and summarization into one billable model call
  • Keep the same versioned output contract as the managed-service architecture
  • Prove PII safety without trusting the model's text output verbatim

Users & stakeholders

  • Architects weighing an LLM-based pipeline against first-party services
  • Risk owners who need to see what guards the model output
  • Finance owners: no discount applies to Foundry-hosted DeepSeek, so token usage is the whole story
  • Engineers running and polling the benchmark from the browser

Value & measured outcome

  • Best accuracy of the three: 3.34% WER overall
  • Best cost of the three: about 52.3% cheaper per call than Architecture 1
  • Most balanced across speakers: 3.14% REP / 3.82% CUSTOMER
  • Finest turn granularity: 112 turns vs 85 from the Speech SDK
The trade being measured. Architecture 2 replaces two governed cognitive services with one general-purpose model under a prompt. The repository answers the obvious objection with defence in depth: the model's placeholders are converted back into explicit spans, the spans are re-applied to the original text deterministically, and the summary is scrubbed of every detected literal value afterwards.

3. Processing pipeline and latency boundaries

Five measured stages and two network round trips: the streaming transcription that runs with the call, and a single Foundry request that returns redaction and summarization together. The regex scan and the two redaction stages are local and in-process, and each one is timed on its own rather than folded into the model call.

4. How model output is constrained

The model proposes; deterministic code disposes. Nothing the model writes reaches the redacted transcript directly.

Before the call — regex hints

  • Six patterns scanned per turn: email, phone number, SSN, credit card, IP address, date of birth
  • Each hint carries category, turn id, offset, length, and the matched text
  • Hints are passed inside the user message as candidates, never applied as redactions
  • The model still makes the final PII decision, including for categories no regex covers

During the call — schema and prompt

  • System message is the repository prompt file, used byte for byte
  • Response format is a strict JSON schema with exactly two properties: summary and conversation
  • Every turn must round-trip its id, participant, channel, offset, and duration
  • Temperature is pinned to 0
  • A malformed or contract-violating response is retried up to the configured attempt limit; tokens from all attempts are billed and counted

After the call — reconstruction

  • Each [CATEGORY] placeholder is aligned back against the original turn text to recover the exact removed span
  • Failure to align is an error, not a silent pass
  • Recovered spans are re-applied to the untouched source turns, so the redacted transcript is derived from the original audio's words
  • The source conversation is asserted unmutated after processing
  • The summary is scrubbed of every recovered literal value, case-insensitively
Residual risk worth stating. Recall depends on the model: an entity the model never marks is never recovered as a span, so it is neither redacted in the transcript nor scrubbed from the summary. That is exactly what the PII leakage rate and recall metrics are there to expose, and it is why annotated ground truth is a first-class upload.

6. Features and non-functional requirements

Functional

  • Per-channel streaming transcription with locally controlled commit boundaries
  • Finer turn segmentation than the classic recognizer — 112 turns vs 85
  • Single-call PII redaction plus issue-focused summarization
  • Typed placeholder redaction of conversation and summary
  • Optional WER scoring and optional PII precision / recall / F1 scoring
  • Full token accounting for cost comparison, including retried attempts

Non-functional

  • Asynchronous — streaming runs at 1×, so runs are submitted and polled
  • Early handoff — downstream work is submitted as soon as this architecture's own STT result lands, not after all three engines
  • Resilient — per-channel transcription errors and Foundry failures are isolated
  • Deterministic output — temperature 0 plus schema-strict responses
  • Verifiable — every model claim is re-derived from the source text
  • No secrets — Entra ID token per run, no keys in the repository
  • Portable prompt — the prompt is runtime configuration copied into the container, not code

Measured position in the benchmark

  • Accuracy: 1st of 3 — 3.34% WER, roughly half the classic recognizer's error rate
  • Latency to transcript: 504.4s on a 504.2s call — effectively real time, reported as latency.stt_seconds
  • Downstream: one model call plus three local stages, summed into latency.downstream_seconds
  • Cost: 1st of 3 — $0.014834 discounted per call, $1,483.44 per 100,000 calls
  • Per-participant balance: 3.14% REP / 3.82% CUSTOMER, the tightest spread of the three

Cost model inputs

  • Audio hours are multiplied by channel count because each channel is submitted independently: 0.280093 hours for the benchmark call
  • MAI transcription is priced per submitted audio hour with the 90% Speech discount applied
  • DeepSeek input and output tokens are priced separately with no discount
  • No cached input tokens were reported, so the cached rate contributes nothing
  • Totals exclude hosting, storage, egress, and any separate Voice Live host-model charge

7. Deployment and runtime notes

Local runtime

  • docker compose up --build starts the backend on port 8000
  • cd frontend && bun install && bun run dev starts the UI on port 3000
  • The host ~/.azure profile is mounted so the container can authenticate and refresh
  • The prompt file is copied into the backend image as runtime configuration
  • uv run python data/stt.py exercises the STT stage alone from the CLI

Configuration

  • AZURE_FOUNDRY_ENDPOINT and AZURE_FOUNDRY_DEPLOYMENT select the model; the chat route shape is derived from the endpoint form
  • AZURE_FOUNDRY_API_VERSION defaults to 2025-04-01-preview and is omitted for endpoint styles that do not take it
  • AZURE_FOUNDRY_MAX_ATTEMPTS defaults to 2
  • SYSTEM_PROMPT_PATH points at the prompt file
  • AZURE_REQUEST_TIMEOUT_SECONDS defaults to 300

Identity and network

  • Key auth is disabled on the Speech resource and on the Foundry deployment; managed identity is the only path
  • In Container Apps, grant the identity Cognitive Services Speech User for Voice Live
  • Outbound WebSocket must be allowed — a locked-down VNet breaks this architecture first
  • Keep egress open to *.cognitiveservices.azure.com and *.services.ai.azure.com
  • Voice Live requires a host model parameter even for transcription-only use; that inference path may be gated separately in a tenant

Provisioning

  • The checked-in Bicep creates the resource group, the Foundry resource, and the DeepSeek deployment on the Global Standard SKU with local key auth disabled
  • The deployment script asserts that the Azure CLI is installed and logged in first
  • Deployment outputs map directly onto the Foundry endpoint and deployment environment variables
  • The Speech resource used for Voice Live is referenced by configuration, not created here

8. Current implementation vs the complete intended pipeline

AspectImplemented todayIntended / complete pipeline
Redaction and summarization A single structured call, reported as one llm_api_call stage carrying combined_pii_and_summary: true; the local transcript_redaction and summary_sanitization stages are timed separately. Unchanged — this is the intended shape. Splitting them would add a round trip and a second token bill for no contract benefit.
Entity confidence Spans derived from placeholders carry no confidence score, unlike the Azure AI Language path. Confidence would need to be requested in the schema and validated; scoring today relies on exact span agreement rather than thresholds.
Cached default comparison The checked-in results file holds STT metrics and pricing usage only, so the UI reports PII accuracy as not scored for that historical run. A live run with annotations attached produces the architecture block plus precision, recall, F1, category accuracy, alignment rate, and leakage rate.
Token lifecycle One Entra token per run; the Voice Live socket is not reconnected mid-call. Reconnect with a fresh token for calls that outlive the token, which matters for a long-lived service rather than a nine-minute benchmark.
Architecture 4 Not implemented and not part of the three-way benchmark. A future Azure Communication Services option combining call audio, STT, and PII handling.
